Luồng tổng thể

Nhà cung cấp→collect_*→validate_*→normalize_*→upsert→cổng chất lượng

Điểm vào: ingest_eod / ingest_index / ingest_news trong src/data/pipelines.py. Mỗi hàm trả về IngestResult gồm số dòng, các vấn đề kiểm tra và phán quyết chất lượng. Lô dữ liệu dưới ngưỡng bị gắn cờ below_threshold và không bao giờ dùng cho bước sau.

Giai đoạn 1 — Nhà cung cấp

DataProvider ABC (fetch_eod / fetch_index / fetch_news). Các triển khai: FixtureProvider (ngoại tuyến, dòng seed tất định), HttpJsonProvider (JSON qua HTTP có thể cấu hình với ánh xạ đường dẫn chấm), SSIFastConnectProvider (nguồn chính: JWT qua Market/AccessToken, Market/DailyOhlc + Market/DailyIndex — VERIFIED_2026-09-27), YahooChartProvider (dự phòng EOD .VN — xem dưới) và RssNewsProvider (feed RSS/Atom: strip HTML, pubDate RFC822/ISO, ghép mã thật theo ranh giới từ). create_provider(source) phân giải id trong registry, market_provider_chain(primary) cho chuỗi chạy tự động (ssix_finipro → yahoo → vndirect → tcbs → dsc); configs/sources.yaml chứa 16 nhà cung cấp (11 đang bật) với lựa chọn theo nghiệp vụ + chuỗi dự phòng.

Nguồn EOD đã kiểm chứng (2026-09-25): YahooChartProvider — chart API query1.finance.yahoo.com/v8/finance/chart/{SYM}.VN. Ba hành vi quan trọng được mã hoá: (1) User-Agent mô tả — UA mặc định httpx bị 429; (2) OHLCV Yahoo đã adjust chia tách → provider un-adjust qua events=split (FPT 11:10, 2026-09-21); (3) dòng placeholder volume=0/null bị bỏ, không bao giờ bịa. trading_value ≈ close × volume (Yahoo không có trường turnover — xem §8 DATA_SOURCES.md).
# offline (fixture, mặc định — luôn chạy được)
python -m apps.worker.cli ingest --dataset prices --source fixture \
  --start 2026-09-01 --end 2026-09-05 --symbols FPT,VCB

# thật (Yahoo, đã kiểm chứng 2026-09-25: 62/62 dòng, quality 94.88)
python -m apps.worker.cli ingest --dataset prices --source yahoo \
  --start 2026-09-01 --end 2026-09-25 --symbols FPT,VCB,HPG,ACB

Yêu cầu Gmail (T018): SMTP chỉ chấp nhận App Password 16 ký tự (tạo tại myaccount.google.com/apppasswords, bật Xác thực 2 bước) — mật khẩu thường → 535; thử lại nhiều lần → Gmail đóng kết nối. Dashboard cảnh báo khi password lưu ≠ 16 ký tự; lỗi SMTP được map sang tiếng Việt.

Giai đoạn 2 — Thu thập

collect_eod(provider, symbols, start, end), collect_index(...), collect_news(provider, since) — các wrapper mỏng kiểm tra supports() và trả về bản ghi độc lập nhà cung cấp (EODBar / IndexBar / NewsItem).

Giai đoạn 3 — Kiểm tra

validate_eod / validate_index / validate_news phát sinh các bản ghi ValidationIssue: kiểm tra miền giá trị (giá âm, high < low), tính nhất quán (thứ tự OHLC), độ phủ cửa sổ (thiếu ngày giao dịch), tính duy nhất (khóa trùng). classify_issue() ánh xạ mỗi vấn đề tới một chiều chất lượng.

Giai đoạn 4 — Chuẩn hóa

normalize_eod / normalize_index / normalize_news ánh xạ bản ghi thành dict sẵn sàng cho CSDL: phân giải symbol → stock_id, ép kiểu Decimal, tem xuất xứ (id nhà cung cấp, fetched_at). Symbol lạ trở thành None (bỏ qua, không bao giờ bịa).

Giai đoạn 5 — Cổng chất lượng (§39)

Sáu chiều — đầy đủ, hợp lệ, nhất quán, duy nhất, tươi mới, chính xác — kết hợp bằng trung bình có trọng số kèm tái chuẩn hóa trên các chiều khả dụng. freshness_score dùng số học Decimal. Kết quả được lưu vào data_quality_scores.
